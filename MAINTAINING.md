# Maintaining the Jmix AI Agent Toolkit

## Structure

- **One branch per Jmix major**: `v2` (Jmix 2), `v3` (Jmix 3), … The repository
  **default branch** is the current stable major, so `HEAD` points at it. The branch
  **is** the version: there is no in-repo version resolution.
- Each branch is **self-contained**:
  - `content/` — `guidelines-block.md` (the marker-delimited block merged into the
    project's own guidelines file) + `skills/<skill>/SKILL.md`. The `jmix` skill is
    the umbrella the block points at; the rest are per-artifact skills.
  - `install.sh` / `install.ps1` — installers. Each holds its branch name in
    `CONTENT_REF` (sh) / `$ContentRef` (ps1) and installs from that branch's `content/`.
  - `.studio/` — `studio-meta-data.json` (Studio wizard steps) and its schema;
    `skills-manifest.json` (skill list, store paths and hash for Studio), generated by
    `gen_skills_manifest.py`.
  - `tests/`, `.github/workflows/` — installer tests and CI: installer lint and tests,
    skill frontmatter lint, manifest regeneration (committed by CI on pushes to `v[0-9]*`).

## How install works

- **CLI**: `curl -fsSL .../jmix-agent-toolkit/<branch>/install.sh | bash` starts the
  wizard. The script downloads its own branch tarball (`CONTENT_REF`), copies
  `content/skills` into a store (`~/.agents/.jmix/skills/<branch>/` globally,
  `<project>/.agents/skills/` locally), symlinks each skill folder into `.agents/skills`
  unless that is the store, merges `content/guidelines-block.md` into the project's
  `AGENTS.md`, and registers the chosen MCP servers. The open convention
  (`.agents/skills`, `AGENTS.md`) is always on; Claude Code is the only choice:
  enabled by default, with `--claude=false` / `-Claude:$false` to skip the
  `.claude/skills` links and the block in `CLAUDE.md`. Studio passes the choice
  explicitly as `--claude=true|false` / `-Claude:$true|$false`. A local run migrates the
  old `<project>/.skills/` store; with `--backup-existing-files` it moves replaced local
  skill folders to `<project>/.agents/.jmix/backups/`, outside the dirs agents scan.
  The store paths in `skills-manifest.json` (`STORE` in `gen_skills_manifest.py`) must
  match the installers'; the test suites check the local one.
- **Hidden compatibility aliases**: the old `--conventions` / `--agents` CSV
  (`-Conventions` / `-Agents`) of `skills` and `agents-md` still work: `claude` in the
  list enables Claude Code, its absence disables it, and an explicit Claude flag wins.
  They stay because released jmix-cli and user scripts pass them. Never document
  them publicly (help, README) and never print a deprecation warning: Studio <= 3.0.4
  treats any stderr output as a failed step.
  PowerShell's generated `Get-Help` syntax still lists the named parameters; the
  authored help text and examples omit these aliases.
- **Jmix Studio**: the **AI Agents Toolkit** wizard computes the branch from the project's
  Jmix major (`v<major>`), fetches `.../v<major>/.studio/studio-meta-data.json` (falling
  back to the default branch if that branch does not exist yet), then runs that branch's
  `install.sh` / `install.ps1` with `--content-ref` / `-ContentRef` set to it. An IntelliJ
  IDEA Registry override can switch all of this to a feature branch for pre-merge testing.

## Skill frontmatter

Codex before 0.142 and Junie parse `SKILL.md` frontmatter as strict YAML and skip a
skill whose frontmatter fails to parse; an unquoted `: ` inside a `description` is
enough, so quote such descriptions. `tests/check_skill_frontmatter.py`, run by
`.github/workflows/skills-lint.yml` on changes under `content/skills/`, enforces strict
YAML without a BOM, `name` matching the folder (at most 64 characters), and a non-empty
`description` of at most 1024 characters.

## Cutting a new version branch (e.g. Jmix 4 → `v4`)

1. Branch from the latest: `git switch v3 && git switch -c v4`.
2. Update `content/` for the new major (`guidelines-block.md`, the stack in `skills/jmix/SKILL.md`, and the other `skills/`).
3. Set the branch identity in both installers:
   - `install.sh`: `CONTENT_REF="v4"`
   - `install.ps1`: `$ContentRef = 'v4'`

   Then replace the other `v3` that name this branch: both installers' help, `tests/`,
   and the README's install URLs (`grep -rn v3 install.sh install.ps1 tests/ README.md`).
4. Regenerate the manifest: `python3 .studio/gen_skills_manifest.py`.
5. Run the tests (without `jq` the sh suite skips its MCP checks; without `python3`, its
   wizard and SSE tests):
   - `bash tests/test_install_sh.sh`
   - `pwsh tests/test_install_ps1.ps1`
   - `python3 tests/check_skill_frontmatter.py` (needs PyYAML)
6. Push the branch. When the new major becomes the stable one, make it the default branch:
   `gh repo edit jmix-framework/jmix-agent-toolkit --default-branch v4`.
