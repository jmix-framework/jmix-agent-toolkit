# Jmix AI Agent Toolkit

Installers that set up AI coding agents (Claude Code, Codex, OpenCode, Junie, ...) for Jmix
projects: Jmix skills, a guidelines block in `AGENTS.md` / `CLAUDE.md`, and MCP servers.
No build step: shell and PowerShell scripts, Markdown skills, JSON metadata.

## Where to look

- `content/skills/<skill>/SKILL.md` — the skills; `jmix` is the umbrella skill.
  `content/guidelines-block.md` — the block merged into a project's guidelines files.
- `install.sh` / `install.ps1` — the installers: interactive wizard plus the subcommands
  `skills`, `agents-md`, `mcp`, `mcp-jetbrains`, `mcp-context7`, `playwright`.
- `tests/` — functional installer suites (temp `HOME` and project dirs) and the skill
  frontmatter lint.
- `.studio/` — read by Jmix Studio from the branch: `studio-meta-data.json` (wizard steps and
  per-OS commands, schema next to it) and `skills-manifest.json` (generated by
  `gen_skills_manifest.py`, regenerated by CI on push).
- `.github/workflows/` — installer lint and tests, skills lint, manifest regeneration.
- Consumers outside this repo: Jmix Studio (`com.haulmont.jmixstudio.ai.toolkit` in
  jmix-studio) and jmix-cli (`AgentToolkitInstaller`).

## Documentation

- `README.md` — for users: install commands, Claude Code option, flags, skills store layout, MCP.
- `MAINTAINING.md` — branch model, how install works, skill frontmatter rules, cutting a new
  version branch.

## Version branches

- One branch per Jmix major (`v2`, `v3`, ...); the default branch is the current stable one.
  The branch is the version.
- Keep the mechanics identical on every maintained `v*` branch: installers, tests, CI,
  `.studio/` metadata and generator, README and MAINTAINING. Branches differ only in
  `content/` (skills and guidelines block, written for their Jmix major, never synced) and in
  the branch identity: `CONTENT_REF` / `$ContentRef` and `v<N>` in help, tests and README URLs.
- Land a mechanics change on one branch, then port it to the others in a sync commit (as
  `3fb296f` did for v2). This diff must show branch-identity lines only:
  `git diff v2 v3 -- . ':!content' ':!.studio/skills-manifest.json'`.

## When changing things

- Change `install.sh` and `install.ps1` together, and cover the same scenarios in both suites.
- `install.ps1` must run on Windows PowerShell 5.1 (Studio runs `powershell.exe`): no
  PowerShell 7-only syntax; delete links with `Remove-Link`, never `Remove-Item -Recurse`
  through a junction.
- Released Studio versions read `.studio/*` from the branch and parse installer output, so
  keep them backward compatible: wizard step ids and commands, manifest shape (`store.local` /
  `store.global` stay strings; the `sha256` algorithm matches Studio's `AiSkillsHasher`) and
  the `@@JMIX_CHANGE@@` actions (`created`, `updated`, `backed-up`). Add, do not change.
- Store paths in `STORE` of `gen_skills_manifest.py` must match the installers; commit the
  regenerated manifest with such a change.
